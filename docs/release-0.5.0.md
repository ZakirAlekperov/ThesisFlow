# ThesisFlow 0.5.0-dev — аналитика и отчётность / Analytics & Reporting

**State / Статус: 0.5.0-dev.** Эта версия находится в одном накопительном
кодовым PR, не автоматически считается стабильной после публикации спецификации.

## Реализованная архитектура

- `internal/analytics`: `Build(ctx, Filter, now)` — один пакетный SQLite JOIN
  активных групп, студентов, групповых и личных требований, текущих состояний
  и `accepted_files`. Показатели в БД не дублируются и не кешируются.
- `internal/materials.GroupStatuses` и `statusmatrix.Group` заменяют
  N×M точечных запросов единым пакетным чтением существующих статусов.
- `internal/analytics.Activity`: реальные загрузки из `file_versions`,
  решения о приёмке из `material_events` и возвраты из `review_feedback`.
  Срез календарной недели с началом в понедельник. Это НЕ реконструкция
  исторической готовности.
- `internal/web/analytics_page.go`: интерфейс `/reports`, фильтры,
  группы, таблицы, ссылки на карточку и требование, сравнение групп,
  недельные CSS-диаграммы с доступными числовыми таблицами, печать браузером.
- `internal/reportexport`: настоящая OOXML XLSX-книга (ZIP, 3 листа
  «Сводка», «Студенты», «Документы»), автофильтр, оформленные заголовки,
  замороженная верхняя строка, чередование строк. Записаны только
  *литеральные строки*: нет макросов, формул, внешних ссылок, CDN.
  CSV: `encoding/csv`, UTF-8 BOM и защитный префикс перед значениями,
  которые Excel мог бы воспринять как формулы.

## Как устроены метрики

- `Required`: применимые документы у действующих студентов.
- `Accepted`, `UnderReview`, `NeedsRevision`, `Missing`:
  текущие, взаимно исключающие состояния. Их сумма = `Required`.
- `Overdue`: срок строго до локального дня и статус != accepted;
  дни просрочки считают календарными днями, без ошибки летнего времени.
- `WithApprovedCopy`: наличие ранее/сейчас принятой файловой копии.
  Этот показатель независим от текущего статуса: новая версия на проверке
  не уничтожает ранее принятую.
- `Percent`: количество текущих accepted / required. Если required = 0,
  UI/Excel показывает «Нет данных», а не 100%.
- Активные группы и студенты определяются `archived_at IS NULL`;
  архивы не примешиваются в текущие отчёты.
- Параметры `group`, `q`, `status`, `overdue`, `sort`, `from`, `to`
  сервер проверяет на допустимые значения.
- Экспорт и экран используют один типизированный объект `analytics.Report`
  с одинаковым набором фильтров.

## URL

- `GET /reports` — текущая сводка и журнал событий по неделям.
- `GET /reports/groups/{id}` — отчёт по одной активной группе.
- `GET /reports/export.csv` — экспорт таблицы документов.
- `GET /reports/export.xlsx` — реальная Excel-книга с тремя листами.
- `GET /reports/print` — отдельное печатное оформление для браузерного PDF.

## Ручная приёмка

1. В рабочей тестовой группе через GUI импортировать настоящий Excel на 20
   вымышленных студентов, добавить 10 обязательных документов ВКР.
2. Добавить индивидуальное требование одному студенту: знаменатель увеличен
   только для него.
3. Загрузить тестовые DOCX, вернуть на доработку, затем принять через GUI.
   Просмотреть текущую сводку, ведомость группы и карточку каждого студента.
4. Проверить разницу «Принят» и «Есть принятая копия»: загрузить новую
   неподтверждённую редакцию после принятия предыдущей.
5. Изменить срок на вчерашнюю дату, затем принять файл: просрочка должна
   исчезнуть. В отчёте количество дней просрочки должно быть календарным.
6. Архивировать студента и группу через действующий интерфейс: они не
   должны отображаться в текущем анализе.
7. Проверить поиск по ФИО и ID, фильтры статусов/просрочки, сортировки,
   переход к карточке и якорю документа.
8. Скачать CSV и XLSX с теми же фильтрами. Проверить все три листа
   настоящего Excel, кириллицу, заголовки, замороженную строку и автофильтр.
9. В учебном ID ввести безопасные тестовые строки `=1+1` и
   `+SUM(1,2)`: импортированные значения в Excel должны быть обычным
   текстом, а не исполняемыми формулами.
10. Открыть печатную версию и сохранить браузером в PDF.
11. Выбрать период событий, проверить фактическое количество загрузок,
   принятия и возвратов, не сравнивая это число с текущими статусами.
12. Провести проверку клавиатуры, 200% масштаба и светлой/тёмной темы
   на Windows и macOS; Linux проверить по возможности.
13. Запустить `gofmt -l .`, `go test ./...`, `go test -race ./...`,
   `go vet ./...` и проверить portable builds.

## Ограничения / Limits

- В этой версии статистика текущая; историческая готовность на дату
  **не восстанавливается**. Для неё нужны снимки требований и сроков.
- «Задержка проверки» не считается: текущие события не имеют
  достаточной связи каждого решения с ID рассматриваемой версии.
- Архивные студенты/группы исключены; переключатель включения архива
  отложен до безопасного разделения отчётов исторического и текущего состава.
- Экспорт XLSX намеренно реализует только узкий формат отчётности,
  а не универсальную замену сторонним Excel-библиотекам.
- Для больших групп экспорт документов ограничен 100 000 строк;
  на практике нужно подтверждение в нагрузочных тестах.

## English

0.5.0 adds coherent read-only analytics over one SQLite JOIN, efficient
group status reads, filtering/sorting, overdue counts, drill-down links,
fact-based weekly activity, literal-text 3-sheet XLSX, injection-safe BOM
CSV and browser-printable HTML. Current approval state is distinct from
the previous accepted copy. It does **not** reconstruct historical
readiness or include archived records in active metrics. Manual testing
with real spreadsheets and sample DOCX is required before release.
