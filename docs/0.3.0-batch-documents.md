# ThesisFlow 0.3.0 — пакетная загрузка / Batch document upload

## RU

В карточке студента появилась дополнительная форма «Пакетная загрузка документов».

1. Откройте группу и карточку студента.
2. Напротив каждого необходимого требования выберите свой DOCX, PDF, ODT,
   RTF, TXT или XLSX. Можно выбрать только часть документов.
3. Нажмите «Загрузить выбранные документы».
4. Вернитесь к списку и проверьте статусы «На проверке».
5. Примите или верните каждую версию по отдельности.

Файл сопоставляется с требованием **по ID поля формы**, а не догадкой
по названию. Один файл соответствует одному требованию. Незаполненные
поля пропускаются. Максимум: 10 файлов за запрос, 20 МиБ на файл,
40 МиБ суммарно.

### Безопасность и сбои

- Перед записью проверяется CSRF, принадлежность студента группе,
  применимость требований, количество файлов, их расширения и размеры.
- До первой записи читаются и проверяются все выбранные файлы. При ошибке
  пользовательского ввода **не сохраняется ничего**.
- При сбое диска/SQLite **после начала сохранения** операция не является
  атомарной для всех файлов: уже сохранённые версии остаются.
  Сервер сообщает число сохранённых файлов. Проверьте карточку перед повтором.
- Принятые ранее файлы не удаляются при загрузке новых версий:
  сохраняется обычный процесс проверки и подтверждения.
- Старый маршрут одиночной загрузки продолжает работать; схема SQLite не меняется.
- У формы нет сторонних JavaScript-зависимостей, она работает без интернета.

### Проверка

`go test ./internal/web ./internal/fileversions ./internal/review`

Ручной сценарий: создайте два требования («Глава 1», «Глава 2»);
загрузите два настоящих файла за один POST; проверьте обе записи со
статусом «На проверке». Повторите отправку с пустым полем и убедитесь,
что соответствующий документ не меняется. Попробуйте недопустимое расширение
и убедитесь, что ни одна версия из этой партии не появилась.

## EN

The teacher can now assign several real files to distinct requirement IDs
on the same student's thesis page and submit them in one multipart request.
Empty inputs are skipped. Limits: ten files, 20 MiB per file, 40 MiB total.

The server checks CSRF, student/group scope, requirement ownership, each
extension and all byte limits before writing any versions. Invalid batches
have no effects. **I/O or SQLite failures after saving has started can leave
a partial batch**; the response identifies the saved count so the teacher
can verify/retry manually. Existing accepted file projections are retained
until a new version is approved. The single-file endpoint remains unchanged.

Run `go test ./internal/web ./internal/fileversions ./internal/review`
and exercise the browser form with two real files and distinct requirements.
No React, npm, remote services or schema changes are introduced.
