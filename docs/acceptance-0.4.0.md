# ThesisFlow 0.4.0 — ручная приёмка / Manual Acceptance

**Текущий статус:** код готовится в общем PR #63, стабильный релиз 0.4.0
пока **не объявлен**. Не подменять реальные проверки зелёным CI.

## Что проверяется

- Очередь `/reviews`: только текущий статус under_review у активных
  групп и студентов, ссылка на последнюю загруженную версию; сортировка
  от старых к новым, фильтр группы, пагинация по 50.
- Комплектность `/groups/{id}/completeness`: общие и индивидуальные
  требования; статусы accepted/under_review/needs_revision/missing,
  количество просроченных по локальной дате. При нуле требований —
  «Нет требований», не ложные 100%.
- Предпросмотр `.../versions/{version}/preview`: встроенный PDF и
  plain-text UTF-8. Путь версии проверяется, байты и SHA-256 сверяются
  с SQLite перед отправкой. PDF должен начинаться с сигнатуры %PDF-.
  Используются Content-Type, nosniff, CSP sandbox и запрет встраивания.
- Форматы DOCX, XLSX, ODT, RTF не интерпретируются как HTML/PDF,
  остаются доступными только для скачивания. Нельзя выдавать обычный
  DOCX за встроенный просмотр в браузере.
- Печатный журнал `.../reviews/print`: реальные комментарии и причины
  возврата, выведенные через html/template, сгруппированные по
  требованиям и ID версии, с датой. PDF сохраняет браузерный диалог.

## Подготовка

Используйте временное рабочее пространство или полную резервную копию,
не настоящие персональные документы. Откройте встроенный раздел «Шаблоны»
и скачайте тестовый XLSX с 20 вымышленными студентами, тестовую главу DOCX,
исправленную главу и текстовые образцы. Для PDF используйте реальный
PDF-документ из офисного приложения (не переименованный DOCX).

Перед тестом убедитесь, что базовая приёмка 0.4 (причина возврата и
неизменяемая история) уже проходит.

## Пользовательский сценарий

1. Создайте группу и импортируйте тестовый XLSX обычной формой.
2. Создайте 10 обязательных документов ВКР и хотя бы одно индивидуальное
   требование для конкретного студента.
3. Проверьте страницу комплектности. У выбранного студента должен быть
   на один документ больше, чем у остальных.
4. В другой тестовой группе создайте студента без требований; должно
   отображаться «Нет требований», а не 100%.
5. Загрузите `Глава 1.docx` через браузер. Откройте «Панель
   преподавателя» → «Очередь проверки». Новый файл должен появиться
   сразу после загрузки, без перезапуска сервера.
6. Загрузите исправленную версию этой же главы до первой приёмки.
   В очереди должна отображаться **только последняя** версия.
7. Перейдите по ссылке «Проверить»: должна открыться именно нужная
   версия в карточке студента.
8. Добавьте замечание к версии и верните её на доработку с причиной.
   После подтверждения документ должен исчезнуть из очереди.
9. Загрузите новую версию и примите её. Проверьте актуальный статус
   в карточке, ведомости и комплектности, а также сохранность
   ранних файлов и прежних замечаний.
10. На реальном PDF проверьте «Предпросмотр PDF/TXT» в новом окне.
    На TXT с текстом `<script>` убедитесь, что браузер показывает
    исходный текст, но **не исполняет** его.
11. Проверьте, что DOCX не предлагает предпросмотр и скачивается
    обычным образом. Попытка прямого preview URL для DOCX даёт
    415 Unsupported Media Type.
12. Откройте «Печать журнала замечаний». Проверьте наличие комментариев
    и причин возврата, их версии и даты. Сохраните документ через
    «Печать» → «Сохранить в PDF».
13. Проверьте неизвестный ID студента, чужую версию, неверный ID
    требования, отрицательные/слишком большие GET-фильтры. Не должно
    быть раскрытия чужих файлов, SQL-подробностей или ошибки 500
    вместо ожидаемой 400/404/415.
14. Пройдите страницы светлой и тёмной темы, масштаб браузера 200%,
    клавиатурой без мыши; проверьте длинные ФИО/названия документов.
15. Повторите ключевые операции на Windows и macOS; для Linux —
    по возможности в реальной сборке приложения.
16. Создайте ZIP-бэкап и восстановите в отдельный каталог;
    проверьте, что замечания и статусы не изменились.

Запускайте на финальной ветке PR и интеграционном merge head, а не

## Ограничения

- Предпросмотр PDF основан на проверке сигнатуры и рендерере браузера,
  но **не является полным валидатором структуры и активного содержимого PDF**.
  Даже при sandbox нельзя обещать отсутствие ошибок браузерного PDF-движка.
- Очередь ограничена 50 строками на страницу, до смещения 100000.
  Текущая версия вычисляется при каждом GET из реальной SQLite.
- Процент комплектности использует только *текущий* статус accepted.
  Если старый принятый файл сохранился на диске, но новая редакция
  находится на проверке, текущая готовность уменьшается корректно.
- Полная автоматическая проверка оформления DOCX/ГОСТ остаётся исследовательской
  задачей и не должна блокировать полезную локальную проверку документов.
- Печатный HTML не подписывается цифровой подписью и не является
  официальным заключением комиссии.

## English

Perform manual QA with a real XLSX roster and actual DOCX/PDF/TXT files
through the browser. Verify latest-version-only review queue, scoped links,
current completeness including student-specific requirements, safe inline
PDF/text preview and an escaped print-friendly feedback history. Test
negative routes and cross-platform UI, then backup/restore. Automated tests
cannot substitute for hands-on inspection of the PDF viewer and accessibility.
