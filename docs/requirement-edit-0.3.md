# ThesisFlow 0.3 — редактирование требований / Requirement editing

На странице группы общие требования ВКР получили действие «Редактировать».
Преподаватель может изменить название требования и срок сдачи, сохранив
постоянный ID, историю версий и статусы студентов. Срок можно очистить.

## Правила безопасности

- Формы используют CSRF, ограничение 4096 байт и проверку группы.
- Нельзя изменить требование чужой группы; дубликаты названий отвергаются.
- Если хотя бы один документ требования уже принят, название изменять нельзя:
  имя принятого файла на диске зависит от названия требования.
  Изменение срока сдачи при этом допускается.
- Для будущего безопасного переименования принятого документа нужен
  отдельный механизм переноса с транзакцией/восстановлением.
- Архивирование/удаление требований сознательно не добавлено, чтобы
  не ломать ссылки на ранее сданные файлы.
- Поля «Направление», «Курс» и «Статус группы» на концепт-изображении не
  являются свойствами текущей модели ThesisFlow.

## Acceptance / Проверка

1. Создайте новое требование и поменяйте название и срок.
2. Убедитесь, что ID документа и видимость у студентов сохранились.
3. Загрузите и примите документ реальным файлом, затем попробуйте
   переименовать требование: сервер должен вернуть конфликт 409.
4. Измените только срок: операция должна пройти успешно.
5. Проверьте CSRF, неизвестные ID, повтор названия и неверную дату.
6. Выполните go test ./... и go vet ./....

EN: Requirement editing uses native server-rendered HTML forms. A title
rename is rejected once a file has been accepted because the approved
filesystem filename would become inconsistent. Deadline-only edits remain
available. No JavaScript framework or schema migration is introduced.
