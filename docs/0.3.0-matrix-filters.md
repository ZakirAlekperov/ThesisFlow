# ThesisFlow 0.3.0 — фильтры ведомости / Matrix filters

## RU

На странице `/groups/{id}/matrix` преподаватель может выбрать фильтр:
«Все студенты», «Не сдан», «На проверке», «На доработке»,
«Принят (хотя бы один документ)» и «Просрочен».

Строка студента остаётся видимой, если **хотя бы одно** групповое требование
удовлетворяет выбранному состоянию. Вверху отображается «Показано X из Y».
Фильтр применяется к уже сформированной ведомости и не меняет SQLite.

Просроченным считается требование с непустым сроком в прошлом (местная
календарная дата) и статусом, отличным от «Принят».
Личные, только студенту назначенные требования **не входят** в общую ведомость;
для них нужно открыть индивидуальную карточку ВКР.

При неизвестном значении параметра `status` сервер отдаёт HTTP 400, а не
показывает произвольный HTML. ФИО, заголовки документов и значения по-прежнему
экранируются средствами Go `html/template`.

Проверка: `go test ./internal/web`. Создать несколько студентов с разными
состояниями требований и проверить каждый фильтр, включая пустой результат.

## EN

The group document matrix now accepts a small allowlisted `status` query
parameter: all, missing, under_review, needs_revision, accepted, or overdue.
A student matches when **any** group requirement matches the selected state.
The page shows X of Y matching students and offers a native GET form.

Overdue means a non-accepted requirement whose ISO due date is before the
application host's current local date. Student-only requirements are excluded
from the shared group matrix as before. All calculations are read-only.

Invalid filter keys return HTTP 400. No JavaScript framework or database
migration is required. Test with `go test ./internal/web`.
