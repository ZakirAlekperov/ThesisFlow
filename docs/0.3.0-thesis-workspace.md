# ThesisFlow 0.3.0 — thesis workspace / Карточка ВКР

## RU

Первое небольшое изменение 0.3.0: страница `/groups/{groupID}/students/{studentID}`
стала рабочей карточкой ВКР, а не только списком форм.

- В шапке указаны ФИО, группа и уникальный учебный идентификатор.
- Показываются количество обязательных документов, число принятых файлов,
  доля готовности и счётчики четырёх текущих статусов.
- Счётчики вычисляются из состояния существующих репозиториев на каждом GET;
  новые таблицы или сохранённые проценты не вводятся.
- Для документов выводятся срок, предупреждение о просрочке, версии с
  оригинальными именами файлов, ссылки скачивания, действия приёмки и возврата.
- У каждого документа доступна сохранённая история смены статусов.
- Навигация между требованиями и назад к группе/ведомости/панели преподавателя
  доступна без JavaScript.
- Тема ВКР и приказ редактируются через существующую защищённую форму,
  скрытую в раскрываемом разделе.
- Файлы и данные студентов по-прежнему защищены исходными проверками
  области действия и CSRF. HTML выводится только через `html/template`.

### Проверка

`go test ./internal/web ./internal/materials ./internal/review`

Открыть карточку тестового студента: первоначально «0 из N принято»,
затем загрузить DOCX и убедиться в счётчике «На проверке», принять версию
и проверить обновление «Принято». Создать требование со сроком в прошлом и
убедиться в предупреждении о просрочке. Просмотреть историю статусов и
проверить возможность скачать старую версию.

Ограничение: пока нет пакетной загрузки и прямого обмена файлами со студентами.
Просроченность вычисляется по локальной календарной дате сервера приложения;
она не дублируется в базе.

## EN

First focused 0.3.0 increment: the existing student materials page now acts as a
teacher's thesis workspace without changing the Go/SQLite stack.

- Header: student name, group, unique educational ID.
- Computed on every request: accepted/required progress and the four current
  material-state counters; no denormalized statistics are persisted.
- Requirement navigation, due dates, overdue warnings, immutable version links,
  approval/revision buttons, and saved event history.
- Existing CSRF-protected topic/order form remains available inside a disclosure.
- All user-controlled values are auto-escaped by `html/template`; the existing
  group/student/requirement scope checks and version storage remain unchanged.

Run `go test ./internal/web ./internal/materials ./internal/review` and manually
check a real DOCX upload, review, acceptance and history in the browser.

Not included yet: bulk upload, student portal or external cloud dependencies.
Overdue calculations use the application's local calendar day.
